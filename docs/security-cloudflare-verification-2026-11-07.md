## 1. 可以确认的结论与边界

- **新增版本命中：Undici 7.28.0 有 23 条、sharp 0.34.5 有 3 条。** OSV 精确版本查询与 GitHub Advisory Database（下称 GHAD）的原始受影响区间逐条比对，26/26 一致。它们是 Wrangler → Miniflare 的开发/运维依赖；没有证据表明被打包成线上 WebDAV Worker 的 npm 依赖。Undici 7.x 覆盖这 23 条的综合最低修复版本为 **7.30.1**；sharp 覆盖这 3 条为 **0.35.5**，但不能由此保证任意 Wrangler 组合兼容或不存在其他公告。

- **Cloudflare 仓库历史公告：本次合并官方 API 和页面可见 8 项。** 当前 Wrangler/Miniflare/workerd 均在所列历史修复版之后，或项目没有对应功能；详见第 3 节。近期 Containers 跨租户事件已由平台修复，当前项目没有 Containers/Sandboxes。该结果只覆盖本次可见来源，不能宣称 Cloudflare 全产品、所有历史公告已经穷尽。

**优先关注普通 fetch 的两项。** [GHSA-xjj6-f33q-929c](https://github.com/nodejs/undici/security/advisories/GHSA-xjj6-f33q-929c) 描述：恶意服务端返回超过五层 `Content-Encoding` 后提前断开，内部 stream 产生未处理 error，即使业务 `catch(fetch())` 也可令 Node 退出。 [GHSA-qrxm-fqhp-jwvm](https://github.com/nodejs/undici/security/advisories/GHSA-qrxm-fqhp-jwvm) 描述：TLS 1.2 服务端重协商时换用另一张 CA 信任但主机名不匹配证书，Undici assertion 可崩溃进程；TLS 1.3 无该重协商机制。二者不要求应用显式启用缓存或图片功能，但仍要求工具连接到恶意/受损对端。

**不能泛化成“所有请求都会泄密/SSRF”。** C 组在共享 cache 条件下可能把用户 A 的 Cookie/Authorization 相关响应重放给 B；GHSA-4w7w 还要求 `compose(redirect(), cache())`、originless Agent 和共享 cache，恶意重定向目标会把数据存到原 URL key。它是特定组合下的缓存投毒/跨用户泄露，不能改写成本项目已经有任意 URL SSRF。GHSA-m8rv 的 CRLF 注入要求非 fetch API 的 blob-like `.type` 由不可信输入控制，原公告明确 native Blob 和 fetch 安全；WebDAV 上传 MIME 值不会因此自动触发它。T 组也只是在应用原本使用函数式证书 pinning 时可能丢失回调，不表示 Node 默认 CA/主机名校验全部失效。

**实际调用证据。** Miniflare 的[Cloudflare API fetch](/Users/wfz/workspace/r2-webdav/node_modules/miniflare/dist/src/index.js#L65776)构造并加授权头后在 65803 调用 Undici；[通用 fetch wrapper](/Users/wfz/workspace/r2-webdav/node_modules/miniflare/dist/src/index.js#L72739)直接调用 `undici.fetch`；[dispatchFetch](/Users/wfz/workspace/r2-webdav/node_modules/miniflare/dist/src/index.js#L104129)通过本地 runtime dispatcher 转发请求。 [runtime Pool](/Users/wfz/workspace/r2-webdav/node_modules/miniflare/dist/src/index.js#L103928)用于本地开发连接，dev-registry pool 使用 `127.0.0.1`；其局部 `rejectUnauthorized:false` 不能扩展为 Cloudflare API 全局关闭证书验证。Wrangler 的[代理初始化](/Users/wfz/workspace/r2-webdav/node_modules/wrangler/wrangler-dist/cli.js#L368773)在有代理环境配置时安装 `EnvHttpProxyAgent`。这些是 API 可达性证明，尚不是恶意 WebDAV 客户端可任意操控出站 HTTP 响应的证明。

## 7. 0.0.0.0、remote R2 与线上运行时的边界

[开发启动脚本](/Users/wfz/workspace/r2-webdav/scripts/wrangler-dev.sh#L13)明确使用 `wrangler dev --ip "${WRANGLER_DEV_IP:-0.0.0.0}"`。这会让开发 HTTP 服务可从主机可达网络访问；实际公网暴露仍取决于容器端口映射、防火墙、代理/隧道。可立即采用 `WRANGLER_DEV_IP=127.0.0.1` 的既有覆盖能力；本次未修改配置。`.tmp/xdg` 只是项目配置位置，不是系统权限隔离。

`--ip` 不能单独证明 inspector 在同一地址无鉴权公开。[当前 inspector 实现](/Users/wfz/workspace/r2-webdav/node_modules/miniflare/dist/src/index.js#L99060)对 Host/Origin 做校验（不允许则 401）；这也不能扩大为对所有本地 API 做了完整渗透验证。历史 CVE-2023-7080 已修复，不应拿历史利用方式推断当前可绕过。

当前 [R2 配置](/Users/wfz/workspace/r2-webdav/wrangler.toml#L9)没有 `remote=true`。但[迁移 main](/Users/wfz/workspace/r2-webdav/scripts/migrate-directory-sidecars.mjs#L491)从 Wrangler 取得 `getPlatformProxy`，默认在 504 行检查 `bucketConfig.remote === true`；[代理创建](/Users/wfz/workspace/r2-webdav/scripts/migrate-directory-sidecars.mjs#L510)后对 [R2 执行迁移](/Users/wfz/workspace/r2-webdav/scripts/migrate-directory-sidecars.mjs#L549)，正式模式会 put sidecar 并 delete 旧对象。这意味着一旦操作者按文档打开远程 R2，本地 Node 工具链处理真实生产存储权限；“dev dependency”不能用来降低这个运维边界的重要性，也不能据此宣称远程攻击链已经成立。应在补丁评估完成前限制开发服务到可信网络、远程 R2 会话最小授权、先确认 dry-run；本次未启动/执行该脚本。
